# ADR-003: Polymorphism і Protected Variations для часових слотів

## Статус
Прийнято

## Контекст (QOC)
- **Question:** Як моделювати знижку залежно від часу (`HappyHours`/`Standard`/`Evening`)?
- **Options:** A: if-else за рядком у домені · B: enum з поведінкою за інтерфейсом `TimeSlotPolicy` · C: окремі класи-стратегії + фабрика.
- **Criteria:** Open/Closed · обсяг коду · типобезпека.
- **Conclusion:** Option B: енум-константи реалізують `TimeSlotPolicy.applyDiscount`; новий слот = нова константа. Незнайомий рядок — явна помилка замість мовчазної відсутності знижки.

## Наслідки
* **Позитивні:** немає каскаду if-else; `TableReservation` залежить від стабільного інтерфейсу `TimeSlotPolicy`; якщо правила стануть складнішими — легко замінити енум на повноцінні класи.
* **Негативні:** нові правила (напр. динамічна знижка з БД) потребують переходу від енума до окремих класів.
