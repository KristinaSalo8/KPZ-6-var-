# ADR-003: Polymorphism і Protected Variations для часових слотів

## Статус
Прийнято

## Контекст (QOC)
- **Question:** 
Як моделювати знижку залежно від часу (`HappyHours`/`Standard`/`Evening`)?
- **Options:** 
A: if-else за рядком у домені (погано, бо легко зробити помилку в тексті й складно розширювати)
B: enum, де кожна константа сама реалізує інтерфейс `TimeSlotPolicy`
C: окремі класи під кожну знижку + клас-фабрика
- **Criteria:** 
Open/Closed, обсяг коду, типобезпека.
- **Conclusion:** 
Option B: enum-константи реалізують `TimeSlotPolicy.applyDiscount`
Новий слот = нова константа.
Неіснуючий рядок часу — помилка замість відсутності знижки

## Наслідки
* **Позитивні:** 
немає каскаду if-else; 
головний клас `TableReservation` залежить від стабільного інтерфейсу `TimeSlotPolicy` 
(це Protected Variations)
* **Негативні:** 
нові правила (напр. знижка динамічно береться з БД) потребують переходу від enum до окремих класів (С).
